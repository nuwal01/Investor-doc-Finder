## Decisions & notes
<!-- Key decisions made along the way, so they survive a context reset. -->
- Source status tracked in `sources_status.md`. EDGAR returns HTML 10-Ks/20-F/40-F; **these are converted to PDF on demand, IN-MEMORY (`edgar.py convert_filing_to_pdf` via wkhtmltopdf/pdfkit — no disk, no cache; reworked by `4db3523`) — see §12**. Glossy IR PDFs still come from web_search.
- **Shipped UI is the HTML/JS frontend (`frontend/` + FastAPI `api.py`); `streamlit_app.py` is a debug tool only** — both share PDF resolution via `pdf_delivery.py`. Endpoints: `POST /search`, `GET /search/stream` (SSE progress), `GET /download` (PDF bytes), `GET /history`. Don't let docs imply Streamlit is still primary.
- **history and cache are two SEPARATE SQLite stores.** `history.py`→`history.db` = per-session search log (Recent-searches panel); `cache.py`→`cache.db` = verified-result cache keyed on `(company, fiscal_year, doc_type)`. Different files/schemas/purposes — never conflate them; `db66f4f` left `cache.py` untouched.
- **Search-history backend is SQLite, not Postgres** — Postgres was the original plan, but none exists in this environment (no server, connection string, or deploy infra), so history reuses the project's existing SQLite persistence (zero new infra). Revisit only if real deployment infrastructure appears.
- Precedence change (accumulate-then-sort): the graph runs its **full source chain** so multiple verified candidates can be compared. Trade-off: higher latency + more fetches (the Fix-2 latency regression, ~3s → ~60s). `MAX_WALL_SEC` (45s) bounds it, but batches near the budget remain non-deterministic.
- **No hallucination guard exists in `intent.py`** (contrary to earlier claims/docs). The AMBIPAR-class protection is (a) `resolver._raw_token_override` (narrow, CSV-backed) and (b) the verify.py company-identity divergence gate (the durable fix). intent.py was intentionally left untouched.
- **Body-read fix was an O(n²) accumulation bug, not a cap issue** — `BODY_READ_MAX_SEC` stayed at 15; the fix replaced `content += chunk` with a join. Root-caused by measurement, not by guessing a bigger cap.
- **Lazy mirror fires on the real "primary verified nothing" signal, not a guessed "thin primary" count threshold.** The verification-failure trigger needed agent.py (verification lives there), so this was deliberately a 2-file change rather than a single-file web_search.py heuristic with a magic constant. Skip-on-primary-win removes the latency; fire-on-primary-fail preserves fallback breadth.
- **4118s AMBIPAR batch anomaly = unexplained outlier, disregarded.** The "machine sleep" explanation was asserted without evidence, then checked against Windows Kernel-Power/Power-Troubleshooter logs and **NOT supported** (no ~68-min sleep/wake gap). Cause unknown; the clean 12/15 run had no such anomaly.
- Fix 4 scope limit: give_up reason "source blocked" left unimplemented (lives in `agent.py._give_up_node`; likely true root cause of issuer 403s is verify.py's non-browser UA — flagged for a future task).
- Spec deviation (intentional): `_select_final` sorts PDF-before-HTML via `0 if is_pdf else 1` (raw `is_pdf` bool ascending would put HTML first, contradicting the PDF-preferred rule).
